## A17 (2026-07-12) — bead `pow-q7n`: the SPEC-READINESS INTAKE LENS is an IN-PIPELINE two-tier ladder at the head of `kSpecReviewCircuit` (not an intake-time governor check); determinism is confined to the tier where a HOLD is never wrong, and the coarse/ready JUDGEMENT is ONE cheap agent; A16's guard is EXTENDED to a FOURTH shape

**Decision:** the 2026-07-11 opus wide run proved the coarse backlog is not spec-ready: 4 of 7 beads gated at `spec_review` on real adr-alignment/coherence findings because their COARSE descriptions produced weak specs, and ~42 opus agents discovered that AT the spec committee — downstream of the most expensive fan-out in the circuit. This bead adds the cheap pre-flight bar that catches it first. The autonomous calls:
(1) **The lens is IN-PIPELINE in `grid_assets`, NOT an intake-time governor check** — the bead's own open SCOPE question, answered. It rides machinery that already exists (the circuit, the `CriticCapability` verdict transport, the `Gate` park), it needs no operator step, and it fails fast: `specify` gains `dependsOn: {readiness-route}`, so a HELD bead spawns NO specify agent and NO 4-critic spec fan-out. A governor-side check would have to be remembered, and would duplicate the transport.
(2) **A TWO-TIER ladder, cheapest first** — `intake` (a deterministic `ServiceCapability`, ZERO agents) → `readiness` (ONE agent) → `readiness-route` (zero agents). One agent replaces the ~18-agent round the wide run burned per coarse bead (`specify` + the 5-lane spec committee + up to 2 auto-respec rounds).
(3) **The calibration that FORCED the split, and the argument against more determinism.** Measured over the 14 live beads (`bd show <id> --json`): the 7 wide-run beads — the 4 that GATED and the 3 that PASSED alike — span 537–2763 description chars / 1–7 concrete anchors / 0–2 ADR refs, and `pow-q7n` itself (which Nico ranked to DRIVE) sits at 1505/1/0. **No scalar threshold separates the 4 that gated from the 3 that passed without ALSO holding the beads the governor ranked to drive.** A deterministic coarse/ready judge would be a false-HOLD machine, and a false hold STALLS the governance track itself — strictly worse than a wasted specify round. So determinism is confined to the tier where a hold is NEVER wrong; the coarse/ready call is the agent's.
(4) **Tier 1 is NARROW BY CONSTRUCTION, and A13(10)'s fence is SCOPED OFF human prose.** It asserts exactly two things: a DRIVEABLE type, and a NON-EMPTY description. It applies NO placeholder fence (`todo`/`tbd`/`???`) and NO length floor to the human-written `Bead.description`. A13(10)'s fence is defined over the SPEC (`acceptanceCriteria` + `design`) — fields the specify AGENT writes to a known contract — and turning it on a human's brief parks a legitimately terse chore bead, or one whose prose says `remove the TODO markers` (an author pointing AT work, not deferring it). Round 1 did exactly that and it was a false-HOLD machine on live work. `specStructuralFindings`/`_proseOnly` in `specify.dart` are therefore left BYTE-UNCHANGED, and the round-1 plan's re-homing of those three regexes is DROPPED. Everything else — is the scope carved, is there an acceptance shape, are the constraints cited, is the approach decided — is a JUDGEMENT, and judgement is tier 2's.
(5) **Driveability is CONSUMED from grid_engine (`IssueTypeDriveability.isDriveable` / `driveableTypes`), never re-declared here** — two definitions of "driveable" would drift and produce a park nobody intended (a structural fence greps `lib/` and fails on a local re-declaration). It is LOAD-BEARING, not dead code: `WorkList._isDispatchableWork` is `type.isCore && (!resident || type.isDriveable)` and `SubstationConfig.resident` DEFAULTS TO FALSE — so under a non-resident station (the default, and the shape every fixture here mounts) an `epic`/`decision`/`spike`/`story`/`milestone` bead IS core, DOES mount, and WOULD drive a specify agent + the full committee today. The live `pow-p94` (type `decision`) is exactly that bead. Tier 1 is the circuit-level contract that holds in BOTH arming modes.
(6) **NO model rung is added and NO dependency on `pow-edp` is taken.** `resolveAgentConfig` honors ONLY `harness` from step params on this base (verified by reading it), so a per-step MODEL rung does not exist; adding one would collide with sibling bead `pow-edp`'s surface and inverting the rank order (`pow-q7n` is 3/5, `pow-edp` 4/5). `ReadinessCriticCapability` resolves through the SAME ladder as every other lane, so the day `pow-edp`'s role defaults land, this lane inherits the cheap model for free. Cheapness TODAY is STRUCTURAL (1 agent instead of ~18), not a model pin.
(7) **The HOLD is a `Gate` carrying NO machine-actionable token.** The station has ONE park primitive (A13(1) reuses `gated` rather than minting a state), so mechanically a hold parks exactly as a spec escalation does. What makes it a REFINEMENT ASK and not a ruling is its CONTENT: `renderIntakeHold`/`renderRefinementAsk` name every finding and carry the lens's rationale VERBATIM, addressed to the governor's refine lever. No `refine:` prefix is minted — A15(3) DELETED exactly such a token on the grounds that "a machine-actionable gate prefix nothing reads is a doc that lies"; a wire gets minted when a consumer exists to read it, not before.
(8) **`IntakeCapability` GATES DIRECTLY (departing from A13(2)'s always-COMPLETE gating-lane contract) and OWNS the readiness lane's round-freshness wipe.** It is the A9 `PinDiffCapability` posture: a pre-lane step whose gate WITHHOLDS the lanes. Unlike `spec-validation` — which runs BESIDE the critics, so early-gating saves nothing — this tier's entire value IS the agent it prevents, so grading into a route would defeat it. It also wipes `.grid/critique/`, because A15(5)'s `clear-critique` only wipes DOWNSTREAM of `specify`: on a `grid rework` round (same worktree, no re-key, so the verdict path is byte-identical) the readiness lane would otherwise read the PREVIOUS round's `bead-readiness.json`, and the `nodePath` stamp cannot fence it. Two wipes, two lane-sets, A15(5) untouched.
(9) **The ladder is deliberately OUTSIDE the `pow-ui8` REWIND set.** Every readiness step is UPSTREAM of `specify`, so the auto-respec `Rewind` (which re-keys `specify` ∪ its transitive dependents ∪ the route) never re-runs it: a respec rewrites the SPEC, not the BEAD, so re-grading an unchanged bead would burn an agent per round to re-derive the same verdict. Fenced with the engine's own `transitiveDependents` predicate.
(10) **The rubric is `bead-readiness`, not `spec-readiness`** — the committee `specify.dart` already ships IS "the spec-readiness committee" (`pow-6ao`) and grades the SPEC; this lens grades the BEAD, upstream of it. One word keeps the two legible in a prompt, a verdict path, and a gate reason.
(11) **A16 is EXTENDED, not duplicated — the ladder is a FOURTH `code`-circuit head shape.** Re-heading `kSpecReviewCircuit` MOVED the persisted cursor key set again: a session minted under the pre-ladder folded shape and surviving a station BOUNCE has no key at `<bead>/spec_review/intake`, the frontier reads a missing key as `pending`, and the ladder would mount `intake` and then `readiness` — which SPAWNS A REAL AGENT — and could PARK a bead whose build is already running. (Round 1 called `intake` "safe, zero-agent"; that understated it, because `readiness` is the step behind it.) So `classifyCodeShape` gains a FOURTH arm on the same cursor-key PRESENCE signal (`intake` is the current spec circuit's only dep-free step, so presence stays TOTAL), `CodeCircuitShape.folded` is RE-MEANINGED as the frozen PRE-LADDER shape, and that shape gets its own frozen sub-circuit under its own registry id (`spec_review_v2`) reached only from `kFoldedCodeCircuit`. Unlike A16's shape-2 freeze, it KEEPS the three-way `spec-route`: `specify` IS a sibling in that circuit, so a `Rewind` naming it is legal and a shape-3 survivor keeps its auto-respec — no capability degrades. A16(6)'s RETIREMENT condition widens to shape-3 cursors.
(12) **The TEST fixture layer gains an intake-passing work bead (`workBead`), because the engine's shared `bead()` fake PREDATES the intake contract and carries an EMPTY description** — which tier 1 correctly HOLDS. A suite that MINTS its session (leaving `intake` to actually mount and run) must push a bead with a real brief, or it parks at intake and its own proof evaporates; a suite that instead ADOPTS a ladder-complete session (`ladderDoneSession`/`ladderDoneProjection`) never mounts `intake` at all and may keep using the bare fake. This is a FIXTURE fix, NOT a weakening of the contract: the alternative — dropping tier 1's empty-description check so the stale fake keeps passing — would let a brief-less bead reach an agent, and no test should be able to buy that. grid_engine's fake is left untouched (it belongs to another repo, and the contract is this pack's).
**Why:** the fail direction is SAFE by construction (A13(7)): `decideReadiness` fail-closes a MISSING verdict to a hold (`no-verdict`) and an off-ladder letter to `not-ready`, and `IntakeCapability` gates a missing ambient bead — a lens whose whole job is to WITHHOLD an expensive fan-out must never let a transport miss buy a free pass to it. Every arm ends in a `Gate`: a false HOLD a governor unwinds, never a false drive. The migration guard is not theoretical and its negative control is not vacuous — verified by MUTATING `classifyCodeShape` to always return `laddered` and re-running: the PRE-LADDER control FAILS with the survivor really writing an `intake` cursor (the spurious mount this guard exists to prevent), and passes only with the guard in place. Tier 2 reuses `CriticCapability` wholesale (A13(3)'s doctrine — ONE hardened transport stack: canonical file → round-fresh stray → result envelope → fail-closed F, each with its `nodePath` stamp, plus the FT-2 usage merge), overriding only `spawn`, so a hardening landed for the critics holds here too.
