## A22 (2026-07-13) — bead `pow-8qb`: the PR body leads with a HUMAN DIGEST under its own `## Summary` heading; A18's `PrDescription.body` is RENAMED to `.summary`; the trailer-only rule gains its BODY-side belt (`sanitizeDigest`); the digest's SHAPE is taught in the prompt and never checked in code

**Decision:** A18 landed the inferred conventional TITLE and proved it (#52/#53/#13), and its own Status footer defers "the human-readable digest" to this bead. Nico (2026-07-12): "the PR descriptions are better but still lack a human readable digest of the changes." The seam already existed — `PrSection.summary` already LED `kDefaultPrSections` and `renderPrSection` already rendered the model's prose FIRST — so the defect was never a missing section. It was that the prose rendered as BARE, UNLABELED text above `## Circuit receipt` (it read as an accident), its prompt contract was ONE weak line whose exemplar value was the self-describing string `"What changed and why, in a sentence or three."` (a model copies the exemplar, so the exemplar IS the contract), and nothing enforced A18(4) in the NARRATIVE. The autonomous calls:
(1) **ONE prose field, RENAMED to what it is — `PrDescription.body` becomes `PrDescription.summary`** — rather than joined by a second field. `body` had come to mean two different things in one file (the model's prose vs the PR's whole `body`), and a second field would have made "which prose is the digest?" a live question at every call site. The BREAKING rename is cheap (one in-repo consumer, three test fixtures) and the parse stays LENIENT: `PrDescription.parse` reads `summary` and STILL RECOVERS a legacy `body` key, because `parse` is documented fail-safe and a model answering in the shape it half-remembers must not lose its digest — the lost digest is the exact defect this bead fixes. The PROMPT teaches exactly one key.
(2) **The digest gets its OWN `## Summary` heading, and an absent digest drops the heading WITH its section.** Every other section is headed; the one a human actually reads was not. The heading is what makes it legible as a digest rather than a stray paragraph. The empty render stays '' (never a bare heading), preserving A18's absent-data-omits-a-section property exactly.
(3) **A18(4)'s trailer-only invariant is enforced in the NARRATIVE by `sanitizeDigest`, extending A18(3)'s by-construction posture from the subject to the body.** `sanitizeConventionalSubject` already stripped the bead id from the SUBJECT by construction; the body prose had no such belt — the prompt merely ASKED. Now a model that writes the id into the digest anyway (bare, parenthesized, or the `#rN` rework form) still cannot land it in the PR body: the id is REMOVED at render, and the composed body carries it exactly ONCE, on the trailer line. This is the one guard this bead adds, and it protects a NAMED invariant (CLAUDE.md: guards LOUD or GONE). The same pure pass caps the digest at `kMaxSummaryChars` (2000) — an essay, or a pasted diff, must not become the PR body.
(4) **The 2–5 sentence SHAPE is taught in the PROMPT and NOT checked in code — no sentence-count validator, and NO `Gate` on a missing digest.** A18(6) ratified fail-SAFE on exactly this ground ("a PR description is decoration"), and a land must never fail over prose. A thin digest is therefore never a land blocker; a blank one drops its section and the PR still opens. A digest-presence provenance line in the receipt was considered and REJECTED as redundant: the existing `- description: inference | fallback` line already tells a reader which channel spoke.
**Why:** the receipt is PROVENANCE — it says a change was rebased, revalidated and graded. It was never a DESCRIPTION, and it cannot become one: no arrangement of `- rebase: clean` tells a reviewer what the branch does. A18 fixed the title, which is what a reader of `git log` meets; this fixes what a reader of the PULL REQUEST meets, and the two are different artifacts with different readers. The change is deliberately small — no new circuit step, no new cursor key, no second inference call (A18(2): the digest is another FIELD on the SAME one-shot answer), and no new knob. Almost all of the leverage is in the exemplar: the old one asked for "a sentence or three" and demonstrated a placeholder, so it got placeholders; the new one demonstrates a real four-sentence digest written for someone who never opens the diff, which is the only instruction a model reliably follows.
