## A15 (2026-07-12) — bead `pow-ui8`: the spec route ACTUATES `StepOutcome.Rewind`; `specify` is FOLDED into the spec circuit as the route's sibling; the round counter moves from the ledger FILE to the node's `rewindCount` (departing from A14(5)); the `respec:` gate token is DELETED (departing from A14(7)); A4's `nodePath` stamp is re-scoped to a foreign-node fence and the critique WIPE becomes the whole round-freshness guarantee

**Decision:** the_grid `tg-o90` landed the loop edge A14(1) split out (`StepOutcome.Rewind({stepIds}, reason)` — the host re-keys the named siblings ∪ their transitive dependents ∪ self back to `pending` with a bumped per-node `rewindCount`, in-session, with no gate bead and no session re-mint), so the RESPEC arm stops parking and starts actuating. The autonomous calls:
(1) **`specify` is FOLDED into `kSpecReviewCircuit`** as the head step, and the hygiene step now `dependsOn` it. `Rewind`'s contract admits only steps of the rewinding node's OWN circuit, so a route in `spec_review` can only re-key `specify` if `specify` lives there (tg-o90's own fixture models exactly this shape and names the fold as this bead's job). `kCodeCircuit` becomes `spec_review → agent → review → land`; `agent`'s `dependsOn: {'spec_review'}` is unchanged and still resolves to `<bead>/spec_review/route`'s positive terminal. The node path `<bead>/specify` MOVES to `<bead>/spec_review/specify` (the test-suite migration; no lib consumer keys on it — `usageReportPath` derives the telemetry filename from whatever the node path is). The hygiene-step dependency is load-bearing twice over, not cosmetic — see (5).
(2) **The ROUND COUNTER is the route node's `rewindCount`, not the ledger's `round` field** — an explicit departure from A14(5) ("which is also why the ledger, not the nodePath, carries the ROUND COUNT"). A14(5)'s reasoning was sound for its actuation (`grid rework` re-mints the session, so the cursor is GONE by the next round); a `Rewind` does not re-mint, so the cursor SURVIVES and is the honest counter. It is also what the engine's `Rewind` doc prescribes ("A route escalates on its OWN policy first by reading its `rewindCount` back through the ambient `SiblingView`") and it is ZERO I/O — which CLOSES a hole the flip would otherwise open: the old file-derived counter reads 0 forever in the offline/dry-run posture (no workspace dir ⇒ no ledger), which was harmless when the arm parked but would be an unbounded loop now that it actuates, stopped only by the engine's belt. The ledger keeps carrying `round` (the brief's "RESPEC round N of 2") and stays the GUIDANCE channel — A14(5)'s other half is untouched.
(3) **The `respec:` gate-reason convention is DELETED** (`kRespecGatePrefix`, `respecGateReason`) — an explicit departure from A14(7), which minted it as the wire the held `tg-b3k` workaround would parse. tg-o90 superseded that workaround and fenced the convention; the RESPEC arm emits no gate at all, so a "machine-actionable gate prefix" nothing reads is a doc that lies. The `Rewind`'s `reason` replaces it (`respecRewindReason`) and is deliberately COMPACT: the engine never parses it and truncates it into the `step.rewound` flare, and the guidance a re-specify agent actually reads is the ledger, in full.
(4) **The BOUND is unchanged in value and stronger in kind**: `kMaxRespecRounds` (2) still fires strictly before the engine's `kMaxReworkRounds` (3) — which is now a real belt (the host REFUSES a rewind at the cap and parks at a human `Gate`), not just `grid rework`'s ceiling. The ESCALATE arm still `Gate`s (structural F / critic F / no-rationale / respec-cap); the ledger write is still LOUD (`Failed`) when it cannot land; the ADVANCE arm still deletes the ledger.
(5) **A4's verdict-freshness stamp is RE-SCOPED to a foreign-node fence; `ClearCritiqueCapability`'s wipe becomes the WHOLE round-freshness guarantee — and the fold is what keeps it holding.** A4 (bead `tg-bns`) made the stamp the critic step's own `nodePath` on the premise that "the rework mechanic … re-keys the bead id itself to `<bead>#rN` per round, so `nodePath`'s root segment already carries session+round". A14(5) already flagged that this premise did not survive `grid rework` (`SessionScope` re-mints with `workBeadId: bead.id`, so the path is byte-identical round to round). Under a `Rewind` it is inoperative BY CONSTRUCTION: no re-mint, no re-key, only a `rewindCount` bump — so every spec critic's `nodePath` is byte-identical across rounds and `_verdictFromFile`'s `stampedNodePath != expectedNodePath` check can no longer distinguish round N's surviving verdict file from round N+1's. The stamp KEEPS its other job (rejecting a file some OTHER node wrote — the stray-write case) and LOSES the round. This is recorded, not repaired with new machinery, because the belt already carries the weight and the fold STRENGTHENS it: `clear-critique dependsOn specify` puts the wipe in the REWIND SET, so `.grid/critique/` is wiped on every auto-respec wave before any lane can read a stale verdict. That dependency is therefore load-bearing for TWO invariants (no stale grades at the route; no stale verdict FILES at the lanes) and is fenced with the engine's own `transitiveDependents` predicate. The residual — the wipe is best-effort, so a delete failure plus a surviving same-path verdict file could still be misread as fresh — is UNCHANGED by this bead (it was already true of every `grid rework` round per A14(5)); the code comments that claimed the stamp backstopped it are corrected here rather than left lying. No behavior in `committee.dart` changes (A13(3)'s shared transport stack stays byte-identical; the edit is doc-only).
(6) **The (pow-6ao-shape → folded-shape) MIGRATION EDGE is carved OUT to `pow-3p4`, not absorbed.** The fold moves a persisted cursor key, and the engine's frontier reads a missing key as `pending` — so a session minted under the pow-6ao shape and sitting mid-review/mid-land would, on the next station BOUNCE, mount a dep-free `spec_review/specify` and spawn a spurious architect that mutates the work bead. That is exactly the hazard deferred bead `pow-3p4` already exists to guard (it gates the first bounce onto pow-6ao's shape today). This bead ships the FLIP and adds no migration code; `pow-3p4` gates the first bounce onto the folded shape, and its drafted design is now STALE: it classifies TWO shapes, and the fold makes THREE — the shape it currently calls "new" (and migrates TO) becomes one it must also migrate FROM. `pow-3p4` must be re-specified against the folded circuit before it is built.
**Why:** A14(1) split the loop edge to the engine and predicted this follow-up ("This bead ships the power_station half… nothing here depends on `tg-b3k` to compile or pass"). The edge landed as a BETTER primitive than the one A14 anticipated — an in-session re-key rather than a gate-resolve + rework re-mint — and the departures above are exactly where A14's reasoning was downstream of the weaker mechanism: with no re-mint there is no reason to keep the round count in a file, and with no gate there is no gate reason to make machine-actionable. (5) is the third-order consequence of the same fact — no re-mint means no re-key means no round in the path — and is registered because A4 is a ratified-track amendment whose stated premise this bead retires. What the bead asked to keep is kept byte-for-byte: the ledger write, the verbatim rationales, and the brief injection.
**Affects (if promoted):** power_station code: `packages/grid_assets/lib/src/code/respec.dart` (`kSpecifyStep`; `respecRewindReason` replaces `respecGateReason`+`kRespecGatePrefix`; `SpecRouteCapability.run` reads `rewindCount` and returns `Rewind`), `specify.dart` (`kSpecReviewCircuit` folds in `specify`; docs), `code_capabilities.dart` (`kCodeCircuit` drops the standalone `specify` step; registry keyed by `kSpecifyStep`; docs), `committee.dart` (DOC-ONLY: `ClearCritiqueCapability` + `_verdictFromFile` doc comments, per (5)); tests: `respec_test.dart`, `spec_committee_test.dart`, `acceptance/spec_stage_acceptance_test.dart`, `support/asset_fakes.dart` (`kSpecifyNode`), plus the node-path migration in `specify_stage_test.dart`, `station_kernel_test.dart`, `substation_service_bundle_test.dart`, `acceptance/circuit_acceptance_test.dart`, `acceptance/invariant_2_only_the_chokepoint_writes_test.dart`, `acceptance/invariant_4_a37_pristine_source_test.dart`. Amends A4's stamp clause; supersedes A14(1)'s `tg-b3k` split, A14(5)'s counter clause, and A14(7) in full. Beads: `pow-3p4` (deferred) inherits the migration edge and must be re-specified for three shapes. the_grid: none (tg-o90 already landed; this bead only CONSUMES it).
**Status:** **Ratified (Nico, 2026-07-12, ADR interview)** — the actuation-via-`Rewind` content is accepted: **(1)** the fold of `specify` into `kSpecReviewCircuit`; **(2)** `rewindCount` as the round counter (zero-I/O; closes the offline unbounded-loop hole); **(4)** the bound (2, firing before the engine's 3 — now a real belt); **(6)** the pow-6ao→folded migration edge carved to `pow-3p4` (which must be re-specified for three shapes). A15's supersessions of A14 (counter, `respec:` token, `tg-b3k` split) stand. **(5) ADJUSTED — alternative (A), positive round-verification:** A4's freshness stamp is NOT left to a best-effort wipe. Instead the spec-critic verdict CARRIES its `rewindCount` and `_verdictFromFile` verifies `stampedRound == expectedRound` (restoring A4's round-aware-stamp intent with the correct round source); the critique wipe DEMOTES to a belt. The fix is bead **pow-05f** (kicked into the grid). The general principle — a value type that represents state HOLDS that state, never inferring it from a side channel — is the_grid **ADR-0013** (draft).
