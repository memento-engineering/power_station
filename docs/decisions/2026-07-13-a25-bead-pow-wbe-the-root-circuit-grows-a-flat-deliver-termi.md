## A25 (2026-07-13) — bead `pow-wbe`: the ROOT circuit grows a FLAT `deliver` terminal whose advance ACTUATES a bound `DeliveryMethod`; a route's failure channel is a THROWN `RouteFailure`; the composed PR body crosses the value-only delivery seam as a WORKTREE LEDGER — RETIRING pending A5 and pending A7(3), RE-HOMING pending A10's proof point, and RECORDING Nico's ruling that ratified A18(2)'s mechanism relocates

**Decision:** the companion migration of `grid_assets` onto the_grid #56 (`b3a9cf7`, M5 D-4a — routing as a first-class primitive, Nico-ratified). `StepOutcome` narrowed to `{Ok, Failed}`; every routing capability becomes an engine `RouteCapability` emitting a `RouteVerdict {Advance, Rewind, Escalate}`; `SourceControl` lost its commit/push/PR/armed verbs. Nine autonomous calls:

(1) **The ROOT `code` circuit grows a FLAT terminal route step `deliver`**; the `land` `SubCircuitStep` is demoted to a PREPARATION leg (`rebase → revalidate`) and KEEPS its step id, so the `<bead>/land/*` cursor keys and `buildCircuitReceipt`'s reads are untouched. FORCED, not chosen: `isDeliveryTerminal` (`grid_engine/lib/src/sdk/route.dart`) is `circuitPath == beadId && circuit.terminalStepId == stepId`, which is false at a `SubCircuitStep` — a sub-circuit tail delivers NOTHING, so left as-is the station would have silently degraded to commit-only forever.

(2) **All FOUR frozen migration shapes grow the same `deliver` terminal.** A frozen shape follows the `landing` sub-circuit it always SHARED (A16(2)'s own words: "its `code_review`/`landing` sub-circuits are the CURRENT ones"), so it inherits the reshape whether or not it opts in, and an old-shape survivor must still deliver. Safe to re-run because `GitHubPrDelivery` is idempotent (force-with-lease + reuse-an-open-PR). A16's classifier is BYTE-UNCHANGED: it discriminates on HEAD cursor keys and this reshape is at the TAIL, so no fifth shape is minted.

(3) **A route's failure channel is a THROWN `RouteFailure`** — `RouteVerdict` is sealed over `{Advance, Rewind, Escalate}` and has NO failure arm, and `RouteAllocation` catches a throwing body and sinks `AllocationFailed`. Throwing is therefore how a route routes itself to supervision, and it is ALSO the cancellation unwind (the allocation swallows a throw whose token is already cancelled). A bare `StateError` would stamp `Bad state:` into the FT-1 `failureReason` an operator reads; `RouteFailure` carries the reason verbatim.

(4) **The composed PR body crosses the value-only `DeliveryRequest` seam as a WORKTREE LEDGER** (`.grid/pr-body.md`), not in the `Advance` payload — the same idiom the respec ledger, the discovery dossier and the pinned diff already use. A terminal payload is persisted into the session bead's metadata under `grid.result.<nodePath>.*`, and the body is kilobytes. Consequence, declared: an OFFLINE workspace (a synthetic path never on disk) skips the write and delivery opens with an EMPTY body — the fail-SAFE posture ratified A18(6) already requires (a land never fails over PR prose), and the same posture every other worktree-ledger write in this package takes.

(5) **A5 IS RETIRED — and this bead is the retirement A5 itself named.** A5 (**pending**) chose an OPT-IN `TreeVerifiableSourceControl` marker BECAUSE of an engine limit, not a preference: *"`SourceControl.commitAll` … returns `void`, so `LandCapability` has no OTHER signal … Widening the engine interface itself is out of this bead's worktree scope (a the_grid change)"*, and its **Affects** note named the exit condition verbatim: *"A future the_grid change that widens `SourceControl.commitAll` to return a result itself would let this stopgap retire."* #56 is that change and MORE — it REMOVED the commit/push/PR/armed verbs from `SourceControl` outright. So all THREE `is`-detected widenings (A5's `TreeVerifiableSourceControl`, `tg-rm5`'s `ReceiptCapableSourceControl`, `tg-w3c`'s `ReworkAwareSourceControl`) are DELETED, and A18's Affects-note clause "Adds NO fifth `is`-detected widening (A5 posture preserved…)" is superseded with them — that clause is NOT among the points Nico enumerated in A18's MECHANISM-SLICE ratification, its whole content is a statement ABOUT A5's posture, and a clause whose only claim is "this preserves A5's posture" cannot outlive that posture; it falls with A5 and needs no fresh human ruling. **A5's INVARIANT survives, STRENGTHENED**: the same `GitOps.hasUncommittedWork` three-gate probe, still fail-closed on `probeError`, still never-push-on-residue — now UNCONDITIONAL inside `GitHubPrDelivery` rather than detected off a marker a bare `SourceControl` fake could skip entirely (A5 itself noted that hole: *"A plain `SourceControl` … the check is skipped entirely"*).

(6) **A15's, A9's and A17's actuations are RE-HOMED onto the verdict, with no behavior change.** A15's "the spec route ACTUATES `StepOutcome.Rewind`" becomes `RouteVerdict.Rewind` — the SAME `(stepIds, reason)` shape and the SAME `rewindCount` counter, so the `Rewind` line is byte-unchanged and only its supertype moved. A9's empty-delta gate, A15(4)'s ESCALATE arm and A17's intake/readiness HOLD are re-homed onto `Escalate`, which reaches the IDENTICAL park via the engine's default `HumanGate` → `ParkAtGate`. A15 and A17 are RATIFIED, and nothing in their ratified content is contradicted — only the carrier type moved, which #56 forced.

(7) **RESOLVED — ratified A18(2)'s mechanism is RELOCATED as a RATIFIED-CONSEQUENCE, and Nico has RULED.** A18(2) sits inside Nico's ratified MECHANISM SLICE: *"the describe pass runs INSIDE `land` behind an injected `InferenceRunner`, not a new circuit step (avoids a 4th cursor-key shape in pow-3p4's migration surface)."* #56 — which Nico RATIFIED — DELETED the `land` step, so "inside `land`" no longer names a place: the relocation is FORCED by a ratified change, not chosen by this run. **Nico ruled on exactly this, governor-relayed 2026-07-13: "Proceed — it's forced by #56."** That ruling is the ratifying authority; this amendment RECORDS it rather than requesting it. The describe pass moves to the terminal `deliver` route, and A18(2)'s three stated rationales are each still paid: the multi-KB body stays OUT of `grid.result.*` (the `.grid/pr-body.md` ledger, (4) above); the `deliver` node is ENGINE-MANDATED ((1) above), so hosting describe in it costs ZERO extra cursor keys — exactly the cost A18(2) protected; and a `RouteCapability` spawns no supervised process (the engine's own doc: it "never spawns"), so the acceptance suite's "the landing phase spawns no supervised process" property stays true.

(8) **A7(3)'s `withPrOpener` ENRICHMENT SEAM IS RETIRED; A7(3)'s fold-order INVARIANT is PRESERVED.** A7 (**pending**) decision (3) reads: *"`GitHubGridAssets` enriches the git asset via a new `GitSourceControl.withPrOpener` seam … → `canLand` true."* #56 deleted BOTH endpoints — the surviving `SourceControl` declares only `workspaceFor`/`branchFor`/`baseBranch`/`provisionWorkspace`, so there is no `canLand` to flip and no PR verb to enrich the source control WITH. The mechanism is not merely disfavoured; it is UNEXPRESSIBLE. `withPrOpener` and `canLand` are DELETED from `GitSourceControl` (now PROVISIONING-ONLY), and `GitHubGridAssets` binds `ServiceBundle.delivery` instead. **A7(3)'s load-bearing content — its `Nest` fold-order argument ("GitGridAssets is the ANCESTOR, so the land-enrichment must happen at the inner GitHub node") — is PRESERVED EXACTLY**: the inner GitHub node still reads the ambient bundle from above and re-provides it downward; only the enrichment PAYLOAD changed, which is the substitution #56 forces. A7's other decisions are PRESERVED: **(1)** the assets still PROVIDE the concrete `ServiceBundle` (its "EMPTY `sourceControlsByRoot`" sub-clause is already moot — the engine type declares exactly five fields and that map is not among them, so only stale doc PROSE named it, now rewritten); **(2)** `sourceControlOf(TreeContext)` stands; **(5)** the git machinery stays INJECTED as asset ctor params — the `GitOps`/`PrOpener` pair simply lands on the node that now consumes it; **(4)/(6)/(7)** untouched.

(9) **A10 is PRESERVED — only its PROOF-POINT OBSERVABLE re-homes, and the `gitOps` half's consuming node moves.** All three of A10's decisions stand verbatim: **(1)** the carrier read is the quiet, SUBSCRIBING `GitServices.maybeOf`; **(2)** ctor-vs-carrier merges PER-FIELD; **(3)** `GitServices` stays a plain `const` class. What changes is only WHERE the `gitOps` half is CONSUMED: `GitSourceControl` no longer accepts it, so `GitGridAssets` drops the field and `GitHubGridAssets` — which needs BOTH halves to construct a `GitHubPrDelivery` — makes the same per-field-merged, subscribing carrier read instead (`GitGridAssets` keeps its own for the `provisioner` half, so A10(1)'s posture now holds at BOTH nodes). A10(1)'s stated proof point — *"a new test proves re-provided machinery re-derives the seat's source control (offline → live flips `canLand`)"* — names an observable #56 deleted; **the TEST IS KEPT** (its `_ServicesController`/`_ReprovidingServices` infra and two-phase flush intact) and its OBSERVABLE re-homed to `ServiceBundle.delivery` (null → `GitHubPrDelivery`), which proves the IDENTICAL D-H invariant A10 exists to protect: a re-provided carrier RE-DERIVES rather than leaving a stale snapshot mounted.

**Why:** #56 is BREAKING and Nico-ratified, so this package does not get to keep its old carriers; the only questions left to the run were WHERE the verdicts land and what replaces the three stopgaps the engine change dissolved. (1) and (2) are forced by `isDeliveryTerminal`'s definition — getting them wrong is not a style miss but a station that silently stops delivering. (3) and (4) are the two seams the engine left to the asset (a route with no failure arm; a delivery method with no tree access), and each is answered with the idiom this package already uses elsewhere rather than new surface. (5) and (8) retire two PENDING amendments whose mechanisms the engine made unexpressible — filed here rather than silently dropped, and in both cases the INVARIANT each protected is preserved (A5's residue fence, strengthened to unconditional; A7(3)'s fold order, unchanged). (9) keeps a pending amendment whole by moving only the observable its proof point named. (7) is the one clause touching RATIFIED content, and it is recorded under Nico's own ruling rather than claimed by the run.

**Also (mechanical, no decision):** `committee.dart`'s `RouteCapability` is RENAMED `CodeRouteCapability` — grid_engine now EXPORTS an abstract `RouteCapability`, and the local declaration shadowed it, so the class could not name its own new supertype. The step id `route` is unchanged (a persisted cursor key). `federated_grid_assets`' `StepMount` test fake is fixed for the engine's new required `circuit`/`circuitPath` — independent #56 fallout, test-only, beyond this bead's stated grid_assets scope, but it left the workspace red.
