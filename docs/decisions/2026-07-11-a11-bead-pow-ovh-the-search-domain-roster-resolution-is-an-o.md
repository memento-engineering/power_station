## A11 (2026-07-11) — bead `pow-ovh`: the SEARCH domain — roster resolution is an OFFLINE MOUNT of the composing station's delegate tree; the result schema; export-only reads (A37 by construction); bead stores only (code-grep is a sibling, not this command)

**Decision:** the coupled skill+command pattern's first Command ships as `packages/grid_assets/lib/src/search/` — `station_search.dart` (the UI-drivable lib service) + `search_command.dart` (the THIN adapter) — with these autonomous calls inside the bead's prescribed shape (the bead's SCOPE section explicitly left the result schema, code-grep placement, and roster resolution to the run):
(1) **The attached-substation set is resolved by MOUNTING the composing station's `GridDelegate` tree OFFLINE** (`mountedRosterOf(delegate)`: bare `TreeOwner` → `mountRoot` → one `flush` → walk `InheritedBranch<SubstationScope>` in tree order → `dispose`), NOT by attaching to the running station's StationControl surface (RS-4) and NOT by parsing any config. The resident-station context IS the delegate (space-6ds: the roster is authored in the tree — the same seats `up` arms), the mount is the H2 authoring-only shape (pure at build, no wiring, no effects, no stores armed), and search therefore works identically station-up or station-down. It is a ONE-SHOT enumeration at the effect boundary — each run re-mounts fresh, no retained tree, so no reactive state can go stale (D-H). `SearchCommand` takes a `GridDelegate Function()` factory (the composing station curries its context: `runner.addCommand(SearchCommand(delegate: () => SpaceDelegate(...)))`) and OWNS the instance it asked for (disposed after the run).
(2) **The result schema.** Hit = `{id, store, status, type, title, field, snippet}` (the bead named ids/store/status/snippet; `type`/`title`/`field` were added so the discover skill filters and renders without a second lookup). Per-store outcome = a sealed union (`StoreSearched{beadsSearched, hits}` / `StoreAbsent{reason}` / `StoreFailed{reason}`) over a shared `{substation, prefix, root, outcome}` envelope — a search NEVER silently drops a roster seat: an absent store (a coded sibling not checked out — space-6ds mounts its seat regardless) is reported-and-skipped (the same skip-loud posture arming takes), a failed read is isolated per-store, and `hitCount` + per-store `beadsSearched` make "0 hits" distinguishable from "0 coverage". Report = `{query, stores[], hitCount}`; `--json` emits it as ONE JSON object (the skill surface); exit 0 = at least one store searched, 1 = no store searchable (a loud non-answer), 64 = no query.
(3) **The per-store read is `bd export --all` — ONE spawn per store — and A37 is held BY CONSTRUCTION, not by a runtime guard:** the service is built on a seam (`SubstationBeadSource`) with no mutation surface, and the default source (`BdExportBeadSource`) can only issue the export argv (fenced by test: the recorded argv set is exactly `[['export','--all']]`). Never `bd show` (writes `.beads/last-touched` and self-triggers the store's watcher — the live-coexistence trap), never `bd ready` (search needs no ready set — half the spawns of the status fallback), never SQL, sequential store reads in roster order (deterministic output, bounded spawn pressure). No LOUD runtime read-only guard exists because there is nothing to check — no write path exists to refuse (guards LOUD or GONE).
(4) **"Backlog + decision beads" = CORE-typed beads only, ALL statuses.** The 9 upstream core types (task/bug/feature/chore/epic/spike/story/milestone + `decision`) are matched; the_grid's custom lifecycle/infra types (session/step/gate/agent/rig/…) are discovery noise and excluded (`issueType.isCore`, the same filter the status fallback applies). All statuses ride: decisions are usually CLOSED and "have we already decided this" needs them — `status` is on every hit so consumers filter.
(5) **Code-grep does NOT belong in this command** (the bead's open scope question, answered): this Command searches bead STORES; searching working trees is a different faculty (different seams — filesystem/ripgrep, no A37 dimension, different result schema) and becomes a SIBLING command/asset if the discover skill ever earns it. Coupling them would fatten the one deterministic substrate the skill calls.
(6) **Match semantics (deterministic):** case-insensitive substring; field precedence `id > title > description > design > acceptance_criteria > notes > close_reason > labels` with the FIRST matching field naming the hit; the snippet is the matching LINE, windowed to ≤160 chars around the match with ellipses; hits sort by bead id within a store, stores ride in roster (mount) order. An empty query is a LOUD `ArgumentError` (a search has a query — never an everything-matches scan).
(7) **Rider:** `test/track_f_composition_assets_test.dart` carried pre-existing drift against the sibling the_grid checkout (`sdk.Substation(name:, root:)` → the current positional `Substation(name, root)`); the two-line mechanical migration rode this bead because the package suite would not compile otherwise. `grid_assets` gains an `args ^2.6.0` dep (the Command surface), matching `dart_grid_assets`.
**Why:** the offline-mount resolution is the only one that is simultaneously roster-driven (never a hardcoded list — the acceptance's redline), deterministic (no dependence on a live control socket), and already-proven idiom (space_station's roster tests enumerate seats exactly this way); an RS-4 attach would make search fail when the station is down for no reason a read-only query has. Export-only reads reuse the exact read path the status fallback ratified (one-shot snapshot, never per-issue spawns) and keep the live-coexistence fences (the governor armed the live station the same day). The thin-Command layering is the ratified redline (`SCRATCH-pub-capability-and-repo-split.md`: logic UI-drivable, never on the Command) — `SearchCommand.run` only parses argv, resolves the roster, calls the service, renders.
**Affects (if promoted):** power_station code (built this bead): `packages/grid_assets/lib/src/search/station_search.dart`, `packages/grid_assets/lib/src/search/search_command.dart`, `packages/grid_assets/lib/grid_assets.dart` (exports + library doc), `packages/grid_assets/pubspec.yaml` (`args`), `packages/grid_assets/test/search/{station_search_test,search_command_test}.dart`, the track_f drift fix. space_station: the one-line composition (`SearchCommand(delegate: () => SpaceDelegate(...))` on `buildRunner`) lands with its own bead — this worktree is power_station-only. pow-88p (the discover skill) consumes `search --json <query>`'s documented report contract.
