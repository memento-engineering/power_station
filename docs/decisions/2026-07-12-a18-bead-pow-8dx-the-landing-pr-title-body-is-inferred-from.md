## A18 (2026-07-12) — bead `pow-8dx`: the landing PR title/body is INFERRED from the branch diff (not templated from the bead); strict Conventional Commits v1.0.0 is enforced BY CONSTRUCTION; the bead id is demoted to a git TRAILER everywhere — PR, land commit, and the build-agent brief

**Decision:** the landing asset opened every PR as `grid: <bead>` (the_grid PR #46's title is literally "grid: tg-6nf") with a receipt-only body that CLOBBERED whatever prose the agent had authored. Nico's 2026-07-12 directive (reference: Conventional Commits v1.0.0) reshaped the bead mid-flight and SUPERSEDED its round-1 derivation/templating design. The autonomous calls:
(1) **INFERENCE, not derivation.** The round-1 `buildPrTitle`-from-the-bead design is superseded: the title/body come from ONE cheap (`haiku`) one-shot completion over `origin/<base>...HEAD` — the SAME three-dot merge-base range `PinDiffCapability` pins the critics' review scope to (A9(2)), so the PR describes EXACTLY the code the committee graded, and a base that moved forward mid-bead can never widen the description any more than it can widen the review. A title templated off the bead can only ever restate the bead; a title read off the DIFF says what actually changed, which is the whole point of a conventional-commit git log.
(2) **The describe pass runs INSIDE the land step behind an injected `InferenceRunner`, NOT as a new spawned circuit step.** Three reasons, in order of weight: the landing circuit's own doctrine already holds that `rebase`/`revalidate` are `ServiceCapability`s over injected runners ("short, bounded, deterministic"), and a one-shot completion is that same class of operation; a new node would push a multi-KB PR body through the session bead's `grid.result.*` metadata AND mint a fourth persisted cursor-key shape, landing inside `pow-3p4`'s live migration surface (A16) — running it inside the existing `land` step leaves every cursor key byte-identical, so `CodeCircuitResolver` needs no change and no new frozen circuit; and the acceptance suite's "the landing phase spawns no supervised process" property stays true. The HARNESS is reused verbatim (`AgentHarness.spawnFor` — the same renderer the critics ride), so the claude flags, model selection and keychain-auth story are identical.
(3) **Compliance is BY CONSTRUCTION, not by trust.** The model returns PARTS (`type`/`scope`/`breaking`/`description`/`body`), never a subject line, and `sanitizeConventionalSubject` RENDERS the subject: an unknown type falls back, the description is first-letter-lower-cased, period-stripped and word-boundary-truncated to 72 chars, and the bead id is STRIPPED. The emitted title therefore always passes `lintConventionalSubject` — asserted as an invariant over adversarial inputs, not hoped for. Only the FIRST letter is lower-cased, deliberately: an acronym or identifier mid-description keeps its case (`infer the PR title`, never `infer the pr title`), which the v1.0.0 convention permits and readability requires.
(4) **The bead id is a git TRAILER (`Refs: <bead>`, token configurable) and NOTHING else** — in the PR body, in the LAND COMMIT (`grid: land <bead>` is retired: `grid` is not a type, and the id was the whole subject), and in the build-agent brief, which now teaches the policy the agents themselves must follow (directive item 5: the git log is the primary artifact, the PR is second). Inverted tracking (bead ← commit) is preserved; the change log stops carrying foreign narrative. `sanitizeConventionalSubject` strips the id from the subject even when a model writes it anyway, so the prompt's rule has a BELT behind it.
(5) **The describe pass rides the AMBIENT `AgentConfig` ONLY, never the bead's `grid.agent` envelope.** The landing prose is STATION policy, not the bead's work agent: a bead that pins its own coding harness/model must not thereby re-point its PR description at that model. The composition's cheap `model` is merged over the station's params.
(6) **Fail-SAFE over fail-closed, deliberately.** Every describe failure path — no runner wired, no worktree on disk, an unreadable log, an empty delta, an illegal harness×target combo, a non-zero run, a timeout, unparseable output — falls back to a deterministic, id-free bead-derived subject and STILL LANDS. Per CLAUDE.md's "guards LOUD or GONE": this is NOT a guard (it protects no named invariant — a PR description is decoration), so it is documented as decoration rather than dressed up as one, and the LOUD gates it sits behind (the `tg-x1j` residue-subset `Gate`, the lease-refused push `Failed`) are untouched and still fire FIRST, before a token is spent. The one invariant this bead DOES name — **no non-compliant, foreign-reference-carrying title ever reaches GitHub** — is made UNREPRESENTABLE rather than guarded (per (3)), the same posture A16 records.
(7) **The commit LINT is PROVENANCE, not a gate.** The branch's own commit subjects are linted and REPORTED in the receipt (`- commits: 3 (1 conventional, 1 trailered)` plus up to three named off-policy examples). Blocking a land at the very end over a subject line would park a DONE, approved bead over prose.
(8) **`pow-yny` is SUBSUMED.** The receipt no longer WRITES the body: it is one section of a composed document whose FIRST section is the inferred what/why prose. The narrow "compose, don't clobber" fix needs no separate bead. `pow-yny` (OPEN, P3) is closeable-as-subsumed — flagged for Nico, not acted on (no dep edge was added; it would invert the direction).
**Why:** the directive is a strict-quality fix Nico wants LIVE, and it favors "a small cheap-inference call over elaborate templating" — so the design question was never *how to template better*, it was *where the truth about a change lives*. It lives in the diff. Everything else here follows from routing that truth to the two artifacts that outlive the bead (the git log, then the PR) while keeping the tracker id out of both — foreign references exist for INVERTED tracking, and a reader of `git log` must learn what changed and why WITHOUT leaving the repo. The two fail-safe guards ((6): no runner wired, no worktree on disk) are what let the WHOLE offline suite stay free of real git and real `claude` — no acceptance test needed migrating, and an exploding fake runner PROVES zero calls under both.
