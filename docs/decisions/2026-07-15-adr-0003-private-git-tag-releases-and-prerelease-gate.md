# ADR-0003 — Private git-tag releases + a pre-release-gated release process

**Status:** **Partially superseded by practice (2026-08-05)** — **D3/D4 stand; D1/D2 do not.**

## Context

Every cross-repo dependency in the org is a **sibling path-override** today (the gitignored
`pubspec_overrides.yaml` pointing at `../the_grid/packages/*` etc.), generated by
`grid dart link`. A path override couples a consumer to the producer's `main`: **when `main`
takes a breaking change, the consumer stops compiling instantly** — it cannot `dart pub get`,
JIT-run, bounce, or hot-reload until it migrates. This has wedged the resident station
repeatedly (the tkm/#56 arc; and on 2026-07-16 `pow-ebf.4`'s harness-as-data deletion left
`space_station` uncompilable, surfaced only when the station crashed and could not recompile —
the running JIT process had been masking a broken `main`).

Two structural facts constrain the fix:

1. ~~**Every `grid_*` package is `publish_to: none`.** pub.dev is *not* the release channel; a
   "release" of a private repo is a **git tag**, and a consumer pins `git: {url, ref: <tag>}`.~~
   **FALSE SINCE 2026-07-25** — the packages are hosted on pub.dev. See the correction at the
   top of this document. D1/D2 below rest on this premise and are superseded with it.
2. **The tooling is half-built.** The linkage domain
   (`dart_grid_assets/lib/src/dart/pub_links.dart`) already models `PubLink.gitUrl`/`gitRef` and
   a `stable` context — but they are **reserved no-ops**: the emitter only ever writes `path:`
   overrides, and `stable` returns no file. The release service
   (`dart_grid_assets/lib/src/dart/release_service.dart`, the `dart release` command behind the
   `release` skill) does version math, `tagFor` (`<package>-v<version>`), scrub, topological
   `publishOrder`, `--dry-run`, and pub.dev polling — but it **assumes pub.dev publication**
   (inapplicable to `publish_to: none`) and has **zero pre-release support** (no rc/beta change
   class at all).

Git-tag pinning alone stops a consumer breaking *silently*. It does not stop a *release itself*
from shipping a break. The org's goal — **never break a release** — requires the second half: a
**pre-release gate** that validates a candidate against every consumer before it becomes a
stable tag a consumer will trust.

## Decision

Releases of the private repos are **git tags**, and breaking releases are **gated behind a
pre-release (rc) soak** that every downstream consumer must pass before promotion.

### D1 — A release is a per-package git tag; consumers pin `git: {url, ref, path}`.

A "release" of a `publish_to: none` package is a **git tag on its repo**, using the existing
`ReleaseService.tagFor` convention **`<package>-v<version>`** (e.g. `grid_engine-v0.3.0`) —
**per-package**, not per-repo. A consumer depends on it as:

```yaml
dependencies:
  grid_engine:
    git:
      url: git@github.com:memento-engineering/the_grid.git
      ref: grid_engine-v0.3.0
      path: packages/grid_engine
```

Per-package granularity keeps independent versioning and reuses the tag convention already in
the tooling. *(The cost — a consumer of N producer packages tracks N refs — is accepted; the
linkage domain (D2) manages the set as data, and a repo cutting one release moves its packages
in lockstep in practice.)*

### D2 — Un-stub git-ref emission in the linkage domain.

`PubLink.gitUrl`/`gitRef` and the `PubLinkContext.stable` path move from "reserved/no-op" to
**emitting real `git: {url, ref}` dependencies**. The pure function
`pubspecOverridesFor(config, context)` gains a `stable` behavior that resolves each link to its
git-tag pin (the `dev`/`worktree` path-override contexts are unchanged — see D5). This is where
"a dep's linkage is data on the bead, applied by a pure function" (the `grid.dart` design,
`the_grid/docs/SCRATCH-pub-capability-and-repo-split.md`) finally emits the git half.

### D3 — Pre-release gate: breaking changes soak through an rc; non-breaking are validated.

The `release` tooling gains a **pre-release change class** (rc). The process:

1. A producer cuts a **pre-release tag** (`grid_engine-v0.3.0-rc.1`).
2. **Every downstream consumer resolves against the rc and runs `dart analyze && dart test`.**
3. The stable tag (`grid_engine-v0.3.0`) is **promoted only when every consumer passes.**

**"Never break a release" is the property that a stable tag is never born until its rc cleared
every consumer** — a break is caught at rc, on the producer's schedule, never in a stable tag a
consumer trusts.

- **A BREAKING change MUST go rc-first** and pass every consumer before promotion.
- **An additive/fix change is still consumer-validated** but MAY tag directly (no rc soak).
- A "non-breaking" change that fails a consumer's build is, by definition, breaking — the
  validation step is what reclassifies it, and it drops to the rc path.

### D4 — The gate is GOVERNOR-RUN, via the extended release command.

The pre-release gate is executed by the **governor** through the release command
(`ReleaseService` + a new *validate-all-consumers-against-a-candidate* step) — **not CI, not
station-driven**, for now. This reuses the mature tooling we have, needs no new infrastructure,
and stands the process up fastest. *(Evolving the gate to a CI job or a station-driven
validation circuit is a deliberate later step, not a prerequisite — this ADR does not build
either.)*

### D5 — The dev/worktree path-override escape hatch is preserved; tags are the default.

`pubspec_overrides.yaml` remains for **local co-development** — the `dev` and `worktree`
`PubLinkContext`s still emit path overrides, so a developer editing two repos side-by-side is
unchanged. What changes is the **default resolution**: a plain checkout with no overrides
resolves its deps from the **git tags pinned in `pubspec.yaml`** (the `stable` context / D2), so
`dart pub get` — and therefore `dart run bin/space.dart` — **always compiles from the
consumer's own source regardless of any producer's `main`.** A per-bead worktree that resolves
tags can `dart pub get` directly, which **supersedes the `tg-8uz` worktree-override hack** and
retires the space_station absolute-cd `validation_plan` gotcha.

### D6 — Adoption order: producers tag before consumers pin; the_grid first.

The arc is one-directional — a consumer cannot pin a tag that does not exist. So:

1. **the_grid first** — it is the wedge source (#56; `pow-ebf.4`) and unblocks the most
   (`space_station`, `power_station` both depend on it). It adopts the per-package tag
   discipline (D1) and cuts its first release tags.
2. **power_station and genesis** adopt the same discipline for what they produce.
3. **Consumers convert** — `space-td1` (space) and the analogous power_station conversion pin
   their private deps to tags (D1) with the escape hatch (D5).

## Consequences

- The tooling grows two capabilities it lacks today: **git-ref emission** (D2, in `pub_links`)
  and **pre-release support + a consumer-validation step** (D3/D4, in `release_service` +
  the `dart release` command). Both are `dart_grid_assets` work.
- Each producer repo adopts a **tagging discipline** (cut a tag per release; rc-first for
  breaking). This is a per-repo process change, documented in each `CLAUDE.md`.
- The path-override wedge closes: a breaking producer change no longer wedges a consumer's
  `main` — the consumer stays on its pinned tag and adopts the change deliberately by bumping
  the ref (which is exactly `tg-ugj` stacked development: build on a pinned base, restack when a
  new tag lands).
- The `release` skill/command remains the coupled-skill+command pattern (ADR-0001): the skill
  carries the judgement (when to cut rc vs stable, reading the validation results); the command
  carries the deterministic ops (tag, emit, validate, promote) as JSON.

## What this does NOT decide

- **Not** a physical repo split, and **not** taking any package public on pub.dev (the
  `tg-8gv` public-readiness track is orthogonal). Everything here is private git tags.
- **Not** a CI or station-driven gate (D4 is deliberately governor-run for now).
- **Not** the `grid.dart`-envelope-on-the-bead authoring convention in full (`tg-xry`) — D2
  implements the git-emission half of the pure function; the bead-authoring envelope is its own
  downstream bead.
