## A20 (2026-07-12) — bead `pow-edp`: the model ladder splits by `AgentRole`; the station's BUILD rung stays `params['model']` and its GRADE rung is a new `AgentConfig.graderModel`; the asset role defaults are opus/sonnet; the ledger-side proof SUBSUMES `pow-efv`

**Decision:** the role-model split ships inside the bead's prescribed precedence (bead > station > asset role default) with these autonomous surface calls:
(1) **The role is an `enum AgentRole { build, grade }`** (`packages/grid_assets/lib/src/agent/agent_harness.dart`), declared at the SPAWN site by each asset — `AgentCapability`/`SpecifyCapability` pass `AgentRole.build`, `CriticCapability` and its subclass `SpecCriticCapability` pass `AgentRole.grade` — and consumed with exhaustive `switch` (house style). Not a `Capability` getter: the role is an argument of ONE resolution call, and a required named param on `resolveAgentConfig` forces every existing and future spawner to declare it at compile time.
(2) **The station's BUILD rung STAYS `AgentConfig.params['model']`** — the key `space up --model` already writes and every harness already reads — and the GRADE rung is a NEW nullable field `AgentConfig.graderModel` (`space up --grader-model`). The asymmetry is deliberate and is the whole reason the split is wedge-free: `params['model']` is simultaneously the transport key, so one map cannot carry two roles' models at once, and re-homing the build model into a second new field would SILENTLY ignore an unmigrated station's `--model` (or, with a loud guard, wedge the live station until the space_station companion landed). With this shape an unmigrated `space_station` (which pins `params: {'model': 'sonnet'}`) keeps its exact current behavior — build on sonnet, critics on sonnet — and the desired defaults arrive the moment the companion drops its `?? 'sonnet'`. `AgentConfig.stationModelFor(role)` is the projection.
(3) **The asset defaults are `kBuildModelDefault = 'opus'` / `kGraderModelDefault = 'sonnet'`** via `defaultModelFor(role)`, and `resolveAgentConfig` ALWAYS stamps an explicit model into the returned config's `params['model']`. There is no `fallbackModel` and no unpinned spawn: an unpinned `claude` resolved to opus then silently fell back to fable once the weekly limit blew (the 2026-07-11 incident). No runtime guard asserts "the model is set" — it is true by construction (`?? defaultModelFor(role)`), and a guard with nothing to check is a guard that should be GONE.
(4) **The bead's `grid.agent` envelope keeps its shape** (`payload.params.model`, `assets_version` 0.0.1 unchanged) and applies to BOTH roles of that bead's agents — the bead is the MOST explicit rung, and a per-role bead override is surface nobody asked for. A BLANK `params.model` is a new FAIL-CLOSED malformation (`FormatException` in `_parsePayload` → `DomainEnvelopeMalformed` → `StateError` → a per-work `Failed`): a blank model would silently fall through to the role default, so the named invariant — *an envelope that names a model names a REAL one* — is guarded LOUD.
(5) **`UsageReport` gains `model`, parsed from the envelope's `modelUsage` keys** (comma-joined when claude reports more than one; blank/non-string keys dropped; `_resultObject` also recognizes a stream-json array member by `modelUsage` alone) and projected into `grid.result.<nodePath>.model`. The argv proves what we ASKED for; `modelUsage` proves what RAN — and two ids in that map is exactly the silent mid-run fallback shape this bead exists to prevent, so it is reported, never collapsed. FT-2's fail-safe posture is unchanged (an absent/malformed key contributes no field, never a throw). **This SUBSUMES bead `pow-efv`** (P2, deferred — "telemetry: persist the model per node to session metadata"), whose written plan is exactly this codec change: rather than land it twice, steps 5/8/9 adopt pow-efv's design (its `_resultObject` key, its defensive key-trimming helper, its merge-site flow-through proofs), and pow-efv is CLOSED as superseded by pow-edp once the gate is green (`bd supersede pow-efv --with pow-edp`). Every one of pow-efv's six acceptance criteria is met by those steps; nothing is dropped. The alternative — dropping the telemetry half and letting pow-efv ship it — was rejected because the argv only proves what we ASKED for: without the `modelUsage` capture, "the critics really graded on sonnet" is unfalsifiable from the ledger, which is the very property this bead exists to establish.
(6) **The gating lanes are untouched.** `code-validation` (`sh -c` over the bead's Validation Plan) and `spec-validation` (a deterministic `ServiceCapability`) are RUNNERS, not agents: they resolve no `AgentConfig` and name no model. Only the four LLM/agentic spawners carry a role.
**Why:** the bead ratified the model (per-role defaults declared by the spawning asset, station flags overriding them, the bead envelope overriding everything); these are the surface calls the run had to make. Each reuses an established idiom — the exhaustive-`switch` sealed axis (`ModelTarget`), the fail-closed envelope precedent (the blank-model refusal), FT-2's capture-only/fail-safe telemetry merge — and (2) is chosen specifically so the cross-repo landing order cannot wedge the live station, the governance-track failure this bead sits inside.
**Affects (if promoted):** power_station code (built this bead): `packages/grid_assets/lib/src/agent/agent_harness.dart` (`AgentRole`, `kBuildModelDefault`, `kGraderModelDefault`, `defaultModelFor`, `AgentConfig.graderModel`/`stationModelFor`/`merge`/`==`/`hashCode`/`toString`), `agent_domain.dart` (`resolveAgentConfig`'s `role` param + the model ladder; the blank-model refusal), `code_capabilities.dart` + `specify.dart` + `committee.dart` (the four spawners' role declarations; one `result` doc line), `usage_report.dart` (`UsageReport.model`), `grid_assets.dart` (library doc); tests: new `test/agent/role_model_ladder_test.dart`, plus the argv-fence migrations and usage-merge fixtures in `track_h_code_extension_test.dart` / `track_c_critic_test.dart` and the `modelUsage` group in `test/agent/usage_report_test.dart`. Bead graph: `pow-efv` closed as superseded by `pow-edp`. **space_station (NOT this worktree — its own `space-*` bead, per A11's precedent):** `lib/src/up_command.dart` — drop `--model`'s `?? 'sonnet'` default (the role defaults replace it), add a `--grader-model` option, and pass it as `AgentConfig(graderModel: results.option('grader-model'))`. Until that lands the station keeps its current all-sonnet behavior — no wedge, no silent flag regression.
**Status:** **Ratified (Nico, 2026-07-12, ADR interview) — MECHANISM SLICE.** The POLICY (build=opus / grade=sonnet; models ride the bead/asset; per-role defaults declared by the spawning asset, station flags override, the bead envelope overrides all) is Nico's directive, already human-ratified — and PROVEN live (the banner reads "build model opus · grader model sonnet"). This ratifies the autonomous IMPLEMENTATION: **(1)** `AgentRole {build, grade}` declared at the spawn site, exhaustive-switch; **(2)** the `params['model']`/`graderModel` asymmetry (wedge-free cross-repo landing — the whole reason the split can't break an unmigrated station); **(3)** the fail-closed blank-model refusal; **(4)** `pow-efv` subsumed; **(5)** `modelUsage` capture (argv proves what we ASKED, `modelUsage` proves what RAN — two ids = the silent fallback this bead prevents). **REFINED FORWARD:** the per-role model DEFAULTS are superseded by **role → tier → model** (bead **pow-2c9**) — the `AgentRole` axis stands, but the model no longer hardcodes per role; it maps role→tier→concrete-model, and `gather` (the discovery explorers) joins as a third role at the cheap tier.
