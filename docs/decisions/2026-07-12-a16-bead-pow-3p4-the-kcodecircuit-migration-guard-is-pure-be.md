## A16 (2026-07-12) — bead `pow-3p4`: the `kCodeCircuit` MIGRATION GUARD is pure bead→circuit ROUTING at the existing `SessionResolver` seam (zero engine change, no cursor rewrite); THREE shapes are classified by cursor-key PRESENCE; the frozen spec-head shape gets its OWN registered sub-circuit (`spec_review_v1`) running the pre-fold BINARY route

**Decision:** A15(6) carved the fold's migration edge out to this bead and declared its 2-shape design stale ("the fold makes THREE"). Re-specified and built against the folded circuit (`origin/main` `d3e5f06`; engine `eb5537f`). The hazard, confirmed end-to-end: `kCodeCircuit`'s head reshaped TWICE and each reshape MOVED a persisted cursor key (legacy `agent → review → land`, no spec phase → A13(1)'s spec-head, `specify` at `<bead>/specify` → A15(1)'s folded, `specify` at `<bead>/spec_review/specify`); the frontier reads a MISSING key as `pending` (`cursorNodeAt`), so an in-flight pre-fold session surviving a station BOUNCE mounts a dep-free `specify` for a bead already mid-review and spawns a spurious architect that MUTATES the work bead's acceptance/design via bd. The autonomous calls:
(1) **The guard is pure bead→circuit ROUTING at the engine's EXISTING `SessionResolver` seam — NOT a cursor migration or backfill.** `sessionFor` already receives the `SessionProjection` (with its cursor), so a grid_assets-local `CodeCircuitResolver` classifies the ADOPTED cursor and roots the FROZEN shape the session was MINTED under; an old-shape survivor's frontier then simply has no folded spec step to mount, and it continues, lands, and closes exactly as it would have pre-reshape. This holds A13(1)'s wiring-only posture ("the specify stage sequences before build purely via circuit wiring — zero engine change") and keeps the engine at `eb5537f`. The alternative — rewriting each survivor's persisted cursor keys to the new paths — is REJECTED: the cursor is the session's own history (what actually mounted, and where), and a migration that edits it makes the record lie about the run. Routing changes what we mount NEXT; it never falsifies what already ran. All three branches return the engine's `SessionScope` keyed `ValueKey('<bead.id>:session')` (the `SessionResolver` contract), so keyed reconcile is undisturbed.
(2) **THREE shapes are classified, and the shape-2 (spec-head) branch needs its OWN frozen SUB-circuit, registered as `spec_review_v1`.** The naive freeze — pointing shape 2's `spec_review` step at the CURRENT `spec_review` circuit — would inflate a circuit whose head IS `specify` (A15(1)'s fold), re-mounting it at `<bead>/spec_review/specify`: PRECISELY the spawn this guard exists to prevent. So the pre-fold spec circuit is frozen under a NEW registry id (deliberately not `spec_review`, which now resolves to the folded body) and reached only from `kSpecHeadCodeCircuit`. The mechanism this rests on: the inflater derives the NODE PATH from `stepId` (`circuit_scope.dart` — `stepPath(nodePath, step.stepId)`) but resolves the SHAPE from `circuitId` (`reg.circuit(circuitId)`), so the frozen step keeps `stepId: 'spec_review'` — its children still land at `<bead>/spec_review/<lane>` and an adopted shape-2 cursor lines up key-for-key — while the body inflated is the pre-fold one with no `specify` in it. The legacy shape needs no such entry: its `code_review`/`landing` sub-circuits are the CURRENT ones (neither reshape touched them), and a ROOT circuit is handed to `SessionScope` directly rather than looked up by id.
(3) **The frozen spec-head sub-circuit runs the pre-fold BINARY `route` (`RouteCapability`), NOT `spec-route` — a deliberate fail-SAFE degradation.** A15(3)'s `SpecRouteCapability` actuates a `StepOutcome.Rewind` naming `specify`, and a `Rewind` may only name steps of the rewinding node's OWN circuit (the very constraint that FORCED the fold). In the frozen circuit `specify` is not a sibling, so wiring `spec-route` there would emit a `Rewind` naming a non-sibling. A shape-2 session minted between `pow-7nm` and the fold (same node paths, a three-way route) therefore degrades to A13's binary matrix: a fixable spec PARKS at a gate instead of auto-respec-ing. That is the right call for a MIGRATION path — these sessions are already PAST `specify`, so the respec arm is unreachable in practice, and a park is a human unwind, never a spurious mutation.
(4) **Classification is by cursor-key PRESENCE, not STATE.** Every persisted key was written by a `CapabilityHost` that actually MOUNTED, and in every shape the spec/build head is the circuit's only dep-free step — so a non-empty folded cursor ALWAYS holds `<bead>/spec_review/specify`, a non-empty spec-head cursor ALWAYS holds `<bead>/specify`, and a non-empty legacy cursor holds neither. Presence is therefore a TOTAL and sufficient signal. Reading the state instead would misclassify a re-armed `pending` head (D-7's gate re-arm flips a parked node back to an explicit `pending` — key still present), which is exactly the case that must not be read as "never ran". Keys rooted at another bead's id are ignored; a cursor with no keys of our own is FOLDED (a fresh mint, or a bead that never started). A rework round lands there too, correctly: `grid rework` re-keys the prior session's `work_bead` to `<bead>#rN` (A15(2)/A14(5)), so the tree finds no session at `bead.id` and MINTS one with an empty cursor — future rounds gain the current spec stage, and the guard fences only genuine pre-fold survivors. The final fall-through (own keys, no `specify` at EITHER path) is FAIL-CLOSED to legacy: the one thing we must never do is root a circuit that CAN mount `specify`.
(5) **The CURRENT circuit reaches the resolver as a constructor VALUE** (`CodeCircuitResolver(kCodeCircuit)`), not a hard import — so `circuit_migration.dart` imports NOTHING from `code_capabilities.dart` (which imports IT, for the registry entry), keeping the edge one-way with no cycle, and honoring ADR-0008 D-H's "config = VALUES in the tree; impls = DI". The resolver is a const, stateless policy object that caches NO classification: it re-derives on every `WorkBead.build` from the injected (bead, session), which `WorkBead` reads with the SUBSCRIBING `dependOnInheritedSeedOfExactType` (D-H "always watch deps" — never snapshot-and-cache reactive state). Both bounce arms fence this directly by advancing a second cursor tick and re-asserting the routing.
(6) **The RETIREMENT condition is NAMED in the code, because this is a MIGRATION and not a permanent seam.** Once no OPEN session carries a shape-1 or shape-2 cursor (every survivor landed, closed, or was reworked into a fresh round), the file is DELETED, `...kMigrationCircuits` is dropped from `buildCodeRegistry`, and the production composition goes back to `CircuitResolver((_) => kCodeCircuit)`. Recorded in the library doc so the next reader knows this is scaffolding with an expiry, not architecture.
(7) **The shared TEST resolver is retyped to the guarded one** (`kCodeResolver` = `const CodeCircuitResolver(kCodeCircuit)`, typed `SessionResolver`), so the whole acceptance suite drives the SAME wiring production will. It is INERT by construction and that inertness is the proof: every existing fixture's cursor is either empty or carries the FOLDED `kSpecifyNode`, so all 334 pre-existing tests pass byte-identically. **ARMING (out of this repo's diff):** the live station still composes `resolver: CircuitResolver((_) => kCodeCircuit)` in space_station `lib/src/up_command.dart`; the guard arms only when that one line becomes `resolver: const CodeCircuitResolver(kCodeCircuit)`, which must ride the same space_station grid_assets bump that first bounces onto the folded circuit. THIS BEAD GATES THAT BOUNCE.
**Why:** the hazard is not theoretical and the negative controls are not vacuous — verified end-to-end by swapping `kCodeResolver` back to the unguarded `CircuitResolver((_) => kCodeCircuit)` and re-running: BOTH gate arms FAIL with a real spurious `specify` spawn on a mid-review survivor. The guard makes the violation UNREPRESENTABLE rather than detecting-and-tolerating it (CLAUDE.md "guards LOUD or GONE"): it is a TOTAL routing function over a named invariant — **a session that already advanced past its own circuit's head never re-enters the spec phase** — so all three branches are valid shapes and there is no violation state left to throw on. The negative controls assert BOTH spurious-entry channels, not just the obvious one: the specify SPAWN (a process) and the spec-phase SERVICE lanes (`clear-critique`/`spec-validation` run with NO provider spawn — only a cursor/result write betrays them), and they match ANY node path ending in `/specify` so they cannot be fooled by the fold having moved the key.
**Affects (if promoted):** power_station code (built this bead): `packages/grid_assets/lib/src/code/circuit_migration.dart` (NEW — `kLegacyCodeCircuit`, `kSpecHeadSpecReviewCircuitId`/`kSpecHeadSpecReviewCircuit`, `kSpecHeadCodeCircuit`, `kMigrationCircuits`, `enum CodeCircuitShape`, `classifyCodeShape`, `class CodeCircuitResolver`), `code_capabilities.dart` (imports the guard; `buildCodeRegistry`'s `circuits:` spreads `...kMigrationCircuits`; `kCodeCircuit`'s stale `pow-3p4` NOTE rewritten to point at the now-existing guard — no capability behavior changes), `grid_assets.dart` (export); tests: NEW `circuit_migration_test.dart` (classifier + dispatch + frozen shapes + registry) and `acceptance/migration_guard_acceptance_test.dart` (the shape-1 and shape-2 bounce negative controls + mid-LAND termination + a POSITIVE non-vacuity control + a FOLDED no-false-downgrade control), plus `support/asset_fakes.dart` (`kCodeResolver` retyped to the guarded resolver; the private `_codeCircuit` policy fn deleted). Resolves A15(6). the_grid: none (the guard rides the existing `SessionResolver` seam — the point of (1)). space_station: the ONE-LINE arming swap in `up_command.dart`, which must accompany the first bounce onto the folded circuit. Retires itself per (6). EXPLICIT NON-GOAL: `composition_assets.dart`'s `CircuitProvider` (typed on the concrete `CircuitResolver`) is NOT the live seam — `WorkBead` reads the EXACT type `SessionResolver` — and binding it into the kernel seam remains Track G's work; it is not widened here.

**Status:** **Ratified (Nico, 2026-07-12, ADR interview)** — accepted as correct **TRANSIENT scaffolding** for circuit-head reshapes that already happened. A16 is a **MIGRATION guard, not an intake guard** (that is A17/`pow-q7n`): it routes old-shape survivors to a frozen circuit and **refuses to rewrite the cursor** ("routing changes what we mount next; it never falsifies what already ran" — A16(1)), is inert when no survivor exists (A16(7)), and self-retires (A16(6)). Its classify-by-cursor-key-**presence** is, however, the ADR-0013 anti-pattern — the session **infers** its circuit-shape from a side channel instead of **holding** it. The durable decoupling — a session **stamps its circuit-version at mint** and the resolver routes by the held field, ending the frozen-shape accretion — is folded into the_grid **tg-w2r** (the next reshape). A16 stands as-is for the past reshapes; tg-w2r is the last to migrate-by-inference and the first to mint a held version.
