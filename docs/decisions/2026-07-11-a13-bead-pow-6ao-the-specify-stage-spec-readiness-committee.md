## A13 (2026-07-11) — bead `pow-6ao`: the specify stage + spec-readiness committee land as two more `code`-circuit steps; the spec gate is a DETERMINISTIC structural lane; the spec critics SUBCLASS `CriticCapability` for one shared verdict-transport stack

**Decision:** the specify asset (`packages/grid_assets/lib/src/code/specify.dart`) is built inside the bead's prescribed shape (an agentic worktree stage upstream of build + a committee reusing the pluggable machine), with these autonomous calls:
(1) **The circuit shape**: `kCodeCircuit` gains `CapabilityStep('specify')` + `SubCircuitStep('spec_review')` at its head — `specify → spec_review → agent → review → land` — with `agent`'s `dependsOn: {'spec_review'}` resolving through the engine's EXISTING one-hop terminal resolution to `<bead>/spec_review/route`'s positive terminal. This is the scope item's confirmation: the specify stage sequences before build purely via circuit wiring (zero engine change), and the spec gate REUSES `Gate` → `StepState.gated` → the `type=gate` bead + `<bead>#rN` rework re-key (the recommended `gated` reuse; no new state).
(2) **The gating `spec-validation` lane is a deterministic `ServiceCapability`** (`SpecValidationCapability` + the pure `specStructuralFindings`), not an LLM critic — mirroring `code-validation`'s runner-not-agent posture. It always COMPLETES with the grade in its `Ok` payload (`{'grade','transport':'structural','rationale'}`), leaving the route as the single decision point; a spec-less / placeholder / section-less bead grades F with every missing element NAMED (guards LOUD). Its rubric prose ships in the pack like `code-validation.md` does for the sh lane.
(3) **`SpecCriticCapability extends CriticCapability`**, overriding only `spawn` (spec prompt, always the harness — no sh flavor): `result()`/`interpretEvent` are INHERITED, so the entire hardened verdict-transport stack (canonical file → round-fresh stray → result-envelope → fail-closed F, the `nodePath` freshness stamp, the FT-2 usage merge — gate-integrity #3/#4, tg-291) serves both committees with one implementation. `CriticCapability` gained a `@protected rubricSource` getter so the subclass reads the same injected `RubricSource`.
(4) **The rubric-id mapping for the ported pack**: the target ids are the bead's (`spec-validation` gating + `coherence`/`adr-alignment`/`acceptance-testability`/`plan-completeness`); the deprecated source pack's `concreteness` + `decision-density` folded into `plan-completeness` (literalness + decisions-made are one completeness axis at grading time), `scope`'s graph-collision half folded into `coherence`'s graph axis (its decompose semantics ride the route's existing rework gate — the station has no separate decompose verdict), `decisions` became `adr-alignment` over the SUBSTATION `docs/adr/` register with ADR-0000 `A<n>` amendments explicitly binding. Every body was REWRITTEN for the station (Dart tooling, this committee's own machinery as duplication examples, memento terminology, the open/gated/closed status model); a residue fence test (`spec_rubric_pack_test.dart`) greps the pack for the source context's tokens (factory/gas-city vocabulary, Go tooling, foreign ADR paths) and includes a non-vacuity check.
(5) **`RouteCapability`'s hard-block reason genericized** to name its `gating` param (was the hardcoded `'code-validation failed: hard block'`) — the shared route must say WHICH committee's gate fired; the existing route tests assert `contains('hard block')` and pass unmodified.
(6) **The specify brief also sets the bead's `validation_plan` metadata** (`bd update <id> --set-metadata validation_plan='…'`) — the bead text asks for a validation plan mapped 1:1 to acceptance; the machine-run half of that plan IS the downstream code committee's gating command (`_validationPlan` reads exactly this key), so the spec stage owning its content closes the loop from spec to build gate. The stage is READ-ONLY on the tree (no commit/push/PR; bd CLI with `--actor specify` only) and materializes NO pub linkage (it greps; the build spawn keeps `_linkWorkspace`).
(7) **Freshness posture documented, not machinery added**: the committee grades the ambient `Bead` the engine re-provides after specify's bd mutation lands (the same bd-watch → reconcile loop that made the bead ready); capabilities trust ambient state at entry (the tg-83y posture). The fail direction is SAFE by construction — a stale/empty spec grades F and PARKS (a false gate a human unwinds), never a false advance.
(8) **`prompts/spec-critic.md` + `renderSpecCriticPrompt`** added as the Packaged-AI-Asset portable mirror (D-9 symmetry with `critic.md`/`renderCriticPrompt`); the manifest declares the five spec resources + the spec-critic prompt.
(9) **Offline acceptance tests fast-forward the spec phase via cursor adoption** (`kSpecPhaseNodes`/`kSpecGradesAllA` in `support/asset_fakes.dart` — already-complete steps never mount), keeping the existing code-committee proofs byte-focused; the spec phase's own fan-out/gate/provenance proofs live in `acceptance/spec_stage_acceptance_test.dart` (including the REAL structural gate grading a spec-less bead F through the kernel).
(10) **(round 2) The placeholder fence reads PROSE, not QUOTATION** — `specStructuralFindings` strips the spec's markdown quotation contexts (fenced ``` blocks, inline `code` spans, `>` blockquote lines) before matching the banned tokens: a spec that QUOTES a token as evidence (a `// TODO` comment the plan deletes, an ADR clause or gate note cited verbatim) is pointing at work, not deferring it, and must not park the bead — the round-1 regression-risk gap. Plain-prose tokens still trip (word-bounded for `tbd`/`todo`, verbatim for the phrases), and negative-control tests fence both directions.
**Why:** the bead ratified the model (specify is an ASSET; the stage + committee reuse the existing machine; spec-gate reuses `gated`); these are the surface/wiring/porting calls the run had to make. Each reuses an established idiom: the deterministic gating lane mirrors `code-validation`'s posture; the subclass keeps ONE transport stack so future hardenings (the next tg-291-class incident) fix both committees at once; the route genericization is the minimal change that makes a shared capability tell the truth; the fold-in of `concreteness`/`decision-density`/`scope` avoids shipping seven lanes where the bead names five.
