## A14 (2026-07-11) — bead `pow-7nm`: the spec route AUTO-RESPECS a fixable spec (advance | RESPEC | escalate); the decision MATRIX forks per committee (departing from A13(5)); the guidance channel is a WORKTREE ledger; the loop EDGE splits to the_grid `tg-b3k`

**Decision:** a gated spec no longer PARKS for a human by default — a FIXABLE fail auto-loops back to `specify` carrying the failing critics' own rationales as the correction guidance (Nico, 2026-07-11: "it CAN flare to a human, but only as ESCALATION, not the default"). The autonomous calls inside that shape:
(1) **The LAYERING finding, and the `tg-b3k` split (the bead's open SCOPE question, answered: NO).** A route→specify RESPEC loop is **not** expressible as a grid_assets route verdict with zero engine change, and four independent reads of `grid_engine` prove it: `StepOutcome` is a **sealed** union of exactly `{Ok, Failed, Gate}` (`sdk/capability.dart:219`; `grep -c "extends StepOutcome"` → 3) with no rewind arm; a `CapabilityHost` writes only its **OWN** node's cursor (`_persistComplete`/`_persistFailure`/`_persistGate`), so a capability has no affordance to re-key a sibling or an upstream node; `frontier.dart` has **no skip state** (a step is withheld only by a `gated`/`failed` dep, and `dependsOn` is AND-only), so a bounded conditional loop cannot be unrolled in the DAG without every round's five lanes running on the happy path of every bead; and D-7's re-arm flips only the *gated* node back to `pending`, so re-running the route alone re-reads the same sibling grades and re-gates. The loop EDGE is therefore the engine's, and the bead's own scope clause governs ("If the latter, split a the_grid bead; keep the route-verdict + brief-injection here"): **the_grid bead `tg-b3k`** carries the actuation (auto-resolve a machine-actionable gate = close the gate bead + perform `runRework`'s `work_bead → <bead>#rN` re-key, which `SessionScope`'s existing gate-resolve transition already observes). This bead ships the power_station half, complete and self-contained; nothing here depends on `tg-b3k` to compile or pass.
(2) **The DECISION MATRIX forks per committee — an explicit DEPARTURE from A13(5).** A13(5) ("**`RouteCapability`'s hard-block reason genericized** to name its `gating` param … the shared route must say WHICH committee's gate fired"; Why: "the route genericization is the minimal change that makes a shared capability tell the truth") established ONE route capability serving BOTH committees, made honest by parameterizing the gate's NAME. This bead requires the two committees to reach **different decisions over the same grade vector** — a code-committee `D` parks for a human; a spec-committee `D` carrying a rationale AUTO-RESPECS — and a naming param cannot express a divergence that lives in the MATRIX, not in a string. So a new `SpecRouteCapability` (over the pure `decideSpecRoute`) serves the spec committee and `RouteCapability` is left **byte-unchanged** for the code committee. The new posture: **one decision matrix per committee, one gate-naming behaviour across both** — A13(5)'s actual invariant (a hard block NAMES its lane) is preserved in the forked route and fenced by test. **A13(3) is NOT departed from:** the shared verdict-TRANSPORT stack (`SpecCriticCapability extends CriticCapability`) is untouched — the fork is of the DECISION matrix only, and `SpecRouteCapability` reads its grades and rationales out of the very payloads that shared stack writes. One transport stack still serves both committees; a future tg-291-class hardening still fixes both at once.
(3) **The fixable/escalate boundary is the GRADE: `D`/`E` = fixable, `F` = human.** The bead asks that a "scope/decompose F" escalate, and A13(4) is why there is no `scope` lane to read it off ("its decompose semantics ride the route's existing rework gate — the station has no separate decompose verdict"). So an `F` from ANY judgement lane is the scope/decompose-class ruling and escalates (it is also where a fail-closed transport miss lands, whose `F` carries no usable rationale), while a `D`/`E` carrying a rationale is the actionable nit that auto-respecs. The deterministic `spec-validation` F (A13(2)) stays a hard block to a human, unchanged.
(4) **The spread ≥ 3 "human ultimatum" rule is REMOVED from the spec route** (and KEPT in the code route). A spread ≥ 3 across A..F necessarily puts some lane at `D` or worse, so the D/E/F arms already cover every case it caught — and what it did with them (park for a human) is exactly what this bead exists to stop doing by default. This is the rule that parked pow-kzx (A/A/B/D). The spread still rides the advance payload as FT-2 provenance.
(5) **The guidance channel is a WORKTREE FILE** — `.grid/spec/respec.json`, written by the route and read by the next `specify` spawn. Not the session cursor (a rework round re-mints the session, so the `SiblingView` the route graded through is GONE by the time the next specify runs — which is also why the ledger, not the nodePath, carries the ROUND COUNT; note A4's rationale "nodePath's root segment already carries session+round" does not hold across a rework round today: `SessionScope` re-mints with `workBeadId: bead.id`, so the nodePath is byte-identical round to round — flagged, not fixed here; A4's belt, `ClearCritiqueCapability`, still holds). Not the work bead either (A37 — the chokepoint refuses a foreign write; only the spawned agent writes the bead, via the bd CLI, per A13(6)). The file reuses A9(4)'s established idiom (the pinned diff already rides a worktree file rather than an inline prompt) and is deliberately a SIBLING of `.grid/critique/`, which `ClearCritiqueCapability` wipes every round — the guidance must outlive that wipe.
(6) **A rationale-less fixable grade ESCALATES rather than respec-ing blind** (`no-rationale`), and a ledger write that cannot land is `Failed`, not a silent `Gate` — the same LOUD posture A9(3) set for the pinned-diff write ("a missing pinned diff would drop the critics back to free rein — the exact failure being closed"). A respec whose guidance never reaches the next brief would re-specify blind and re-park, which is the toil this bead removes. Auto-respec is BOUNDED at `kMaxRespecRounds` = 2 (strictly below `grid rework`'s own `kMaxReworkRounds` = 3, so the asset's cap always fires before the engine's); the cap flares to a human.
(7) **The gate reason is the machine-actionable TOKEN** — a respec `Gate`'s reason starts with the literal `respec:` prefix (`kRespecGatePrefix`) and names the round + every failing lane's grade and rationale. It is simultaneously the wire `tg-b3k` parses to decide it may auto-resolve, and the human-readable body a governor reads on the parked gate bead today. Every other gate this route emits (a structural F, a critic F, a rationale-less fail, the cap) is a human ruling and carries NO such prefix — that absence is the non-regression fence.
**Why:** the bead ratified the model (auto-respec with the critic recommendations; a human only as escalation). These are the calls the run had to make to land it. The fork in (2) is the one real departure and is deliberate: A13(5)'s shared route cannot express two different matrices, and forking the DECISION while keeping the TRANSPORT shared (A13(3)) is the smallest change that keeps both invariants — the code committee's behaviour is byte-identical, and the spec committee gains the arm the bead asks for. The layering split in (1) is what the bead's own SCOPE clause prescribes for exactly this finding, and it keeps this half a strict improvement the day it lands: a governor's bare `grid rework <bead>` now finds the correction guidance already in the agent's brief (the pow-kzx toil was reading the D rationale and hand-correcting the bead), and `tg-b3k` removes the last human step.
**Affects (if promoted):** power_station code (built this bead): `packages/grid_assets/lib/src/code/respec.dart` (new — the ledger, the sealed `SpecRouteVerdict`, the pure `decideSpecRoute` matrix, `SpecRouteCapability`, the gate reason + the rendered guidance), `specify.dart` (`kSpecReviewCircuit`'s `route` step routes through `spec-route` — its `stepId`/terminal/deps/params unchanged, so no node path moves; `SpecifyCapability.spawn` reads the ledger; `buildSpecifyBrief` gains the optional `guidance` param), `code_capabilities.dart` (the `spec-route` registry entry, beside the untouched `route`), `grid_assets.dart` (export); tests: new `respec_test.dart`, plus `spec_committee_test.dart` (the spec route's D-lane test replaced by the respec/no-rationale pair), `specify_stage_test.dart` (the brief render + the `spawn` SEAM over a real temp worktree), `support/asset_fakes.dart` (`committeeSession` gains an additive `results` param so a fake critic can carry a rationale), `acceptance/spec_stage_acceptance_test.dart` (a fixable spec parks with a `respec:` gate; the build never spawns). the_grid: **`tg-b3k`** (the loop edge — the engine auto-resolves a `respec:` gate into a rework round). `RouteCapability` and the shared critic/verdict-transport stack are UNCHANGED.
**Status:** **Ratified (Nico, 2026-07-12, ADR interview)** — the ENDURING autonomous content is accepted: **(2)** the per-committee decision-matrix FORK (`SpecRouteCapability` distinct from `RouteCapability`, verdict-transport shared) — the departure from A13(5) stands; **(3)** grade-as-boundary (`D`/`E`→respec, `F`→human); **(4)** the spread ≥ 3 "human ultimatum" removed from the spec route (kept in the code route); **(5-guidance)** the worktree ledger `.grid/spec/respec.json` as the correction channel; **(6)** rationale-less→escalate, ledger-write-fail→`Failed`, auto-respec bounded at 2.
